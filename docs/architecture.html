企业 Agent 中台技术方案

DSH 作为平台主基座；自研 Multica Runtime 插件；复用 Multica Server/Daemon 调度不同 CLI；沙箱作为独立运行环境。

完整可编辑版本请查看 architecture.md。

七层架构

层次职责技术选型
用户入口聊天、文件、Runtime 与环境选择自定义 Web、飞书 Bot
统一网关登录、用户映射、消息路由与流式回复现有 Gateway、Keycloak
DSH 基座插件、Skills、MCP、Memory、SessionDSH Profile 与插件体系
Runtime 适配将 DSH Agent 请求转成 Multica 任务自研 DSH–Multica 插件
执行调度机器注册、任务排队、CLI 调用、结果上报Multica Server / Daemon
运行环境个人、项目、临时、持久或本地环境CubeSandbox、现有 VM、本地环境
数据与评测会话、文件、Trajectory 和质量评测PostgreSQL、S3、Langfuse

执行链

自定义 Web / 飞书 Bot
        ↓
统一 Gateway
        ↓
DSH 平台基座（Session、Skills/MCP、用户插件、Memory/Trajectory）
        ↓
自研 Multica Runtime 插件
        ↓
Multica Server → 目标 Daemon → DSH / Codex / Claude Code / Pi
        ↓
个人/项目云端沙箱 或 用户本地电脑

关键原则

  • Runtime 决定谁执行；运行环境决定在哪里执行。
  • 同一会话可切 Runtime，DSH Session 作为平台主记录。
  • 企业 Skill/MCP 由 DSH 管理，通过 Runtime 插件同步到 Multica。
  • 云端优先 CubeSandbox；本地通过 Multica Daemon 连接用户机器。
